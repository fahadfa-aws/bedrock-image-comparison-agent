# Infrastructure Setup

This directory contains infrastructure-as-code templates for deploying AWS resources required by the Bedrock Image Comparison Agent.

## S3 Buckets

The application uses S3 buckets in two regions to store generated images:
- **us-east-1**: For images generated by Amazon Nova Canvas
- **us-west-2**: For images generated by Stability AI models

### Prerequisites

- AWS CLI installed and configured
- AWS credentials with permissions to create S3 buckets and CloudFormation stacks
- Appropriate IAM permissions (see `../iam-policy.json`)

### Deployment

#### Quick Deployment

```bash
cd infrastructure
./deploy-s3.sh dev
```

This will:
1. Deploy S3 buckets in both us-east-1 and us-west-2
2. Configure bucket policies, encryption, versioning, and lifecycle rules
3. Set up CORS for frontend access
4. Output the bucket names for your `.env` file

#### Manual Deployment

**Deploy to us-east-1:**
```bash
aws cloudformation deploy \
  --template-file s3-buckets.yaml \
  --stack-name bedrock-image-comparison-s3-dev-us-east-1 \
  --parameter-overrides Environment=dev \
  --region us-east-1
```

**Deploy to us-west-2:**
```bash
aws cloudformation deploy \
  --template-file s3-buckets.yaml \
  --stack-name bedrock-image-comparison-s3-dev-us-west-2 \
  --parameter-overrides Environment=dev \
  --region us-west-2
```

### Configuration

After deployment, add the bucket names to your `.env` file:

```bash
IMAGE_STORAGE_TYPE=s3
S3_BUCKET_US_EAST_1=bedrock-image-comparison-us-east-1-{account-id}-dev
S3_BUCKET_US_WEST_2=bedrock-image-comparison-us-west-2-{account-id}-dev
S3_SIGNED_URL_EXPIRATION=3600
```

Replace `{account-id}` with your AWS account ID.

### Bucket Features

**Security:**
- Private access only (no public access)
- Server-side encryption (AES256)
- Versioning enabled
- Secure transport required (HTTPS only)

**Cost Optimization:**
- Lifecycle policies:
  - After 30 days: Transition to STANDARD_IA
  - After 90 days: Transition to GLACIER
  - Old versions deleted after 30 days

**Access:**
- CORS configured for localhost development
- Signed URLs for secure image access
- 1-hour URL expiration (configurable)

### Cleanup

To delete the S3 buckets and all resources:

```bash
# Delete us-east-1 stack
aws cloudformation delete-stack \
  --stack-name bedrock-image-comparison-s3-dev-us-east-1 \
  --region us-east-1

# Delete us-west-2 stack
aws cloudformation delete-stack \
  --stack-name bedrock-image-comparison-s3-dev-us-west-2 \
  --region us-west-2
```

**Note:** Buckets must be empty before deletion. Use the AWS Console or CLI to empty buckets if needed.

### Cost Estimation

**Storage Costs (per 1000 images, ~2GB):**
- Month 1 (STANDARD): ~$0.046/month
- Month 2-3 (STANDARD_IA): ~$0.025/month
- Month 4+ (GLACIER): ~$0.008/month

**Request Costs:**
- PUT requests: ~$0.005 per 1000 requests
- GET requests: ~$0.0004 per 1000 requests

**Data Transfer:**
- First 100GB/month: Free
- Additional: $0.09/GB

### Troubleshooting

**Bucket name already exists:**
- Bucket names must be globally unique
- The template uses your AWS account ID to ensure uniqueness
- If deployment fails, check if buckets already exist

**Permission denied:**
- Ensure your IAM user/role has the required permissions
- Update your IAM policy using `../iam-policy.json`

**CORS errors:**
- Update the `AllowedOrigins` in `s3-buckets.yaml` to include your production domain
- Redeploy the stack after changes

### Production Deployment

For production deployment:

1. Update CORS origins in `s3-buckets.yaml`:
```yaml
AllowedOrigins:
  - 'https://your-production-domain.com'
```

2. Deploy with production environment:
```bash
./deploy-s3.sh prod
```

3. Update IAM policies for production access
4. Consider enabling S3 access logging
5. Set up CloudWatch alarms for bucket metrics
